🛰️ 有余 · 体验方案原型

离线缓存 + 弱网记账

地铁、电梯、地下停车场——记账最高频的场景恰恰常常没信号。本方案让「有余」在弱网/断网下也能打开看数据、照常记一笔，联网后自动、幂等地同步，全程给用户明确、可信的状态反馈。第一阶段仅小程序端，离线只放开「新增收支」这一最高频、最安全的操作。

工作原理 · 四层结构

1网络感知层

用 uni.onNetworkStatusChange + getNetworkType 维护全局 online / weak / offline 状态；请求层 fail() 抛出的 NETWORK_ERROR 也触发降级。状态变化驱动全局横幅。

2读缓存层

GET 成功响应按「接口+账本」写入本地存储。断网时首页/流水回落到缓存快照并打「缓存」标记，页面永不空白。

3写队列（Outbox）

断网或写失败时，把「记一笔」入队并乐观上屏（临时 id + 待同步标记）。联网后按序重放，用服务端返回替换本地临时记录。

4幂等去重

每条队列项带客户端生成的 clientToken，后端按它去重。断线重连、重复重放都只会落一笔，杜绝重复记账。

技术要点 · 给工程实现的约束

1. 在哪拦截

复用现有 utils/request.js：fail() 已统一抛 NETWORK_ERROR，这是离线降级唯一入口。新增一层 offline 中间件包裹 http：GET 走「先网络后缓存」，写操作（POST /transactions、/transactions/adjust）走「入队 + 乐观返回」。

2. 存什么（本地存储 key）

youyu_cache_<账本>_<接口> 存 GET 快照 + 时间戳；youyu_outbox 存写队列（每项含 clientToken、payload、ledgerId、本地临时 id、状态、重试次数、失败原因）。全部走 uni 同步存储，与现有 invite.js / theme.js 的用法一致。

3. 乐观上屏与临时 id

离线记的记录用 local_<uuid> 作临时 id 插入列表并打「待同步」；同步成功后用服务端真实记录替换（按 clientToken 匹配），避免闪烁与重复。

4. 幂等（需要后端配合的唯一改动）

POST /transactions 接受可选 clientToken，后端加唯一约束：同一用户 + clientToken 已存在则直接返回原记录，不重复落账。这是保证「断线重连重放不重复记账」的关键，也是本方案唯一的后端改动点。

5. 触发同步的时机

① onNetworkStatusChange 变为在线；② App onShow / 首页 onLoad；③ 用户在同步中心手动触发。队列按入队顺序串行重放，失败项保留并标红，不阻塞后续项。

6. 阶段一范围与保守策略

离线只放开新增收支（覆盖绝大多数记账场景，且不依赖服务端状态）。离线下的编辑/删除服务端已有记录、转账、AA、余额校准暂不入队——弱网下这些操作直接提示「该操作需要联网」，避免复杂的离线冲突。余额展示在有待同步项时标注「含未同步 N 笔」，以服务端为准。

这是可点开预览的静态原型，用于确认交互与视觉方向。确认后我可以据此产出完整 spec（requirements → design → tasks）并落地实现。
