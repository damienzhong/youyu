# 成就系统手工验证清单（任务 10.2）

本文件只列**必须由人在真机或微信开发者工具上执行**的验证项。已经能在开发机上自动复核的部分
（MySQL 的 CHECK 拒绝、ODKU 赋值求值顺序、V33 游标回填 + 老用户零待播报的可自动化部分）
见文末「附录 A：已自动复核的项」，无需人工重跑。

## 前置条件

- **设备**：iOS 一台（iPhone）+ Android 中低端一台（建议 3~4 年前的千元机，`微信 → 我 → 设置 →
  关于微信` 记下微信版本号）。中低端机是必需的：动画掉帧与 Toast 节奏问题在旗舰机上看不出来。
- **构建产物**：`cd miniapp && npm run build:mp-weixin`，产物在 `miniapp/dist/build/mp-weixin`。
- **账号**：准备两个账号。**账号 A**（老用户，库里已有 `BADGE` 行）、**账号 B**（新用户，零数据，
  用来现场解锁成就触发播报）。
- **每项都请记录：设备 / 微信版本 / 基础库版本 / 结论（通过 / 不通过）/ 实际观察**。
  基础库版本在开发者工具「详情 → 本地设置 → 调试基础库」与真机「右上角胶囊 → 关于 → 调试」可见。

## 第 1 组 · 微信开发者工具（先做完这组再上真机）

### 1.1 导入产物，编译零报错

- **做什么**：微信开发者工具 → 导入项目 → 目录选 `miniapp/dist/build/mp-weixin` → 填 AppId →
  等首次编译结束。
- **看什么**：Console 与「编译」面板**零 error**；`pages/achievement/achievement` 出现在页面列表里
  且**不在 tabBar**（底部只有首页 / 报表 / 我的三项）；进入成就页时导航栏标题为「我的成就」，
  下拉能出现刷新动效。
- **为什么必须人工**：任务 9.9 只能在 CLI 跑 `npm run build:mp-weixin`。CLI 构建成功 ≠ 开发者工具
  编译通过——`<canvas type="2d">`、`open-type="share"`、页面级 `enablePullDownRefresh`
  这些都只在小程序编译器里才被校验。
- **覆盖**：需求 9.11（非 tabBar + 页面级下拉刷新）、9.13。

### 1.2 `<canvas type="2d">` 的基础库支持与取节点

- **做什么**：用账号 B 或 A 打开成就页，找**任意一枚已解锁**成就 → 点「保存卡片」。在 Console 里
  观察是否有 `createSelectorQuery` / `getContext` 相关报错。
- **看什么**：能取到 canvas 节点（不报 `node is null`）；卡片能画出并弹出保存结果提示。
  若基础库过低导致 `type="2d"` 不支持，这里会直接失败——**记下失败时的基础库版本号**，
  它就是本功能的基础库下限，需要回填到 `manifest.json` 的 `mp-weixin.libVersion` 讨论里。
- **为什么必须人工**：这是全仓第一处 canvas 绘图（此前 `createCanvasContext` /
  `canvasToTempFilePath` / `type="2d"` 零命中），无既有范本；`fields({ node: true })` 是否返回
  node 只有小程序运行时说得清，H5 与 vitest 都验不到。
- **覆盖**：需求 8.4。

### 1.3 弹层内 `open-type="share"` 能唤起转发面板

- **做什么**：用账号 B 现场解锁成就（见 3.1 的造数据方法）让解锁弹层出现 → 点弹层里的「分享给好友」。
- **看什么**：① 转发面板**确实打开**（弹层是 `position: fixed` 的遮罩，`open-type="share"` 的
  `button` 在遮罩内是否仍生效必须实测）；② **弹层保持展示、不被关闭**（需求 7.13 后半句）；
  ③ Console 里 `onShareAppMessage` 收到的 `res.target.dataset.code` **等于当前播报那一枚的编码**
  （代码里 `dataset` 是首选、`pendingShareCode` 是兜底，要确认走的是 `dataset` 这条）。
- **覆盖**：需求 8.1 后半句、8.3、7.13。

### 1.4 转发卡片 → 点击进入 → 高亮正确项

- **做什么**：1.3 的转发面板里发给「文件传输助手」→ 关闭小程序 → 从聊天里点开那张卡片。
- **看什么**：① 落地页是成就页；② **1000ms 内滚动到该项**并高亮；③ **3000ms 后恢复默认样式**；
  ④ 分享标题含「有余」与该成就名称、长度 ≤30；⑤ 卡片 `path` 形如
  `/pages/achievement/achievement?code=XXX`。
  再补两条负例：把 `code` 手改成不存在的编码、以及超过 64 字符的串（开发者工具「编译模式 →
  添加编译模式 → 启动参数」里填 `code=NOT_A_CODE`）→ **展示不含高亮项的默认页，且不出任何错误提示**。
- **覆盖**：需求 8.3、8.10、8.11、8.12。

### 1.5 未登录经分享卡片进入 → 登录引导 → 登录后回跳并高亮

- **做什么**：清除登录态（开发者工具「清缓存 → 清除数据缓存」）→ 用 1.4 的编译模式带
  `code=<某枚已解锁成就的编码>` 启动 → 走登录 → 登录完成。
- **看什么**：① 未登录时**展示登录引导、不发成就清单请求**（Network 面板里确认没有
  `/api/achievements` 请求）；② 登录完成后**自动打开成就页**并高亮 `code` 指向的那一项
  （`code` 暂存在 `STORAGE_KEYS.pendingAchievementCode`，可在 Storage 面板看到它先出现、
  用掉后被清除）。
- **覆盖**：需求 8.13、8.14、9.14。

### 1.6 `getCurrentPages()[…].route` 的字符串形态

- **做什么**：分别停在记账页、成长页、成就页，在 Console 执行
  `getCurrentPages()[getCurrentPages().length - 1].route`。
- **看什么**：三次分别打印 `pages/record/record`、`pages/growth/growth`、
  `pages/achievement/achievement`——**不带前导 `/`、不带 `.html`、不带 query**。
  `utils/achievementBroadcast.js` 的挂载点守卫（`MODAL_HOST_ROUTES`）与「已在成就页就不再压一层」
  的判断都靠这个字符串精确相等；形态一变，弹层会在不该出现的页面上被丢弃，或在成就页上叠一层同路由页。
- **为什么必须人工**：H5 与 mp-weixin 的 `route` 形态不同（H5 上可能取到 `__route__` 或带 `/`），
  vitest 里是手工 mock 的常量，验不了真机形态。
- **覆盖**：需求 7.1、7.2、7.14、7.16（挂载点与跳转行为的前提）。

### 1.7 需求 8.1 前半句：每一行已解锁成就都有「分享」与「保存卡片」

- **做什么**：用一个**已解锁多枚**成就的账号打开成就页，从上到下逐组、逐行看。
- **看什么**：① **每一枚已解锁**成就行下面都有「分享给好友」与「保存卡片到相册」两个按钮
  （不是只有第一枚有，也不是一个都没有）；② **未解锁**成就行**没有**这两个按钮；
  ③ 点未解锁行（若有误触入口）只出「尚未解锁」提示，不绘制、不转发。
- **为什么单独列出**：任务 9.7 修过一个真实缺陷——9.6 写出的 `.acts` 按钮块落在了 `v-for`
  **外面**，`v-if="a.unlocked"` 因此编译到一个未定义的 `_ctx.a` 上，结果**任何成就都不显示这两个
  按钮**。修法是把「行 + 按钮块」一起包进 `<template v-for :key>`。这类结构性错误在 vitest 里测不到
  （纯函数模块没被波及），只能靠眼睛在真实渲染结果上确认，所以必须复验一次。
- **覆盖**：需求 8.1 前半句、8.2。

### 1.8 弹层布局与 `button` 样式复位

- **做什么**：在「模拟器 → 机型」里切到**小屏机型**（iPhone SE 或 375×667），让解锁弹层出现。
- **看什么**：① 卡片宽 `560rpx`，在小屏上左右**不溢出、不被裁切**；② 「进入成就页」「分享给好友」
  「保存卡片」**三个入口都完整可见、不换行错位、不互相挤压**；③ 三个 `button` **没有微信默认的
  1px 灰边框**（`.au-btn::after { border: none }` 的复位是否生效），也没有默认的圆角/背景残留。
- **覆盖**：需求 7.4、7.13、9.13。

## 第 2 组 · 真机（iOS 一台 + Android 中低端一台，两台都要跑）

### 2.1 解锁弹层入场动画不掉帧

- **做什么**：用账号 B 触发一次解锁播报（见 3.1）。观察入场动画。可在开发者工具的真机调试里
  打开性能面板辅助，但**主判据是肉眼**。
- **看什么**：① 入场动画时长**落在 600~1500ms**（实现取 900ms）内，观感上是「一次完整的放大 + 淡入」，
  不是瞬间出现也不是慢到卡住；② **全程不掉帧、不跳跃**；③ 只有位移 / 缩放 / 不透明度在动，
  卡片高度**不抖**（用 `height`/`top` 做动画在中低端机上必掉帧，实现刻意只用
  `transform` + `opacity`，这一条就是在验它）；④ 点关闭或点遮罩 → **300ms 内**收起。
- **覆盖**：需求 7.4、7.7、7.8。

### 2.2 Toast 节奏（1500ms + 300ms），紧接 300ms 收起动画之后

- **做什么**：造**至少 3 枚**同批解锁（3.1 的方法一次能解锁 5 枚），弹层出现后**立即**点关闭。
- **看什么**：① 弹层收起（300ms）**之后**才开始第 1 条 Toast，两者不重叠、不打断；
  ② 两条 Toast 各展示约 1500ms、之间间隔约 300ms；③ **最多 2 条**（单次播报总计 ≤3 项），
  第 4 枚起不出现；④ 中低端机上 Toast 不糊在一起、不丢一条。
- **覆盖**：需求 7.5、7.6、7.8。

### 2.3 canvas 卡片在 2x / 3x 屏下不模糊

- **做什么**：iOS（3x：iPhone Plus/Pro Max 系列）与 Android（2x 或 2.75x）各保存一张成就卡片，
  存到相册后**放大到 100% 以上**看文字边缘。
- **看什么**：① 四项内容都在：**成就名称、成就描述、解锁日期（精确到自然日）、产品名「有余」**；
  ② 文字边缘**锐利不发虚**（`type="2d"` 需要按 `dpr` 缩放画布，模糊即说明缩放没做对）；
  ③ 卡片上**没有**金额、邮箱、邀请码、账本名称，也没有其它用户的任何标识。
- **覆盖**：需求 8.4、8.5。

### 2.4 相册授权三条路径（每台机器都要跑完三条）

> 三条路径必须按顺序做，且每条之间要把小程序**彻底关闭重进**。`uni.getSetting` /
> `uni.authorize` / `uni.openSetting` 在 H5 上都不存在，这三条**只能真机验**。

- **2.4.a 首次询问**：用一个**从未授权过相册**的微信账号（或先在 `微信 → 设置 → 通用 → 发现页管理
  → 小程序 → 有余 → 权限` 里清掉「保存到相册」）→ 点「保存卡片」。
  **看**：系统授权弹窗出现 → 点「允许」→ 保存成功提示（约 1500ms）→ **停留当前页**，相册里能找到图片。
- **2.4.b 拒绝后再触发**：清掉授权 → 点「保存卡片」→ 在授权弹窗里点「拒绝」。
  **看**：① 出现「需要授权」提示；② **不写相册**；③ **停留当前页**；④ **已展示的成就清单与进度取值
  一字不变**（不刷新、不回到加载态）。随后**再点一次**「保存卡片」：**看**：这次
  **不再发起 canvas 绘制**，而是给出「需要授权」提示 **+「打开系统设置」操作**。
- **2.4.c 系统设置里改回来**：点「打开系统设置」→ 在小程序设置页把「保存到相册」打开 → 返回 →
  再点「保存卡片」。**看**：这次直接保存成功、停留当前页。
- **覆盖**：需求 8.7、8.16、8.6。

### 2.5 保存的幂等与 3000ms 兜底

- **做什么**：① **连点** 5 次「保存卡片」；② 在网络条件很差时（开发者工具真机调试可限速，
  真机可开飞行模式后立刻点）触发一次保存。
- **看什么**：① 连点只画一次、只出**一条**提示，不叠加 Toast；② 3000ms 内没画完 → 结束本次保存、
  **不写相册**、出「保存失败」提示、停留当前页，**之后还能再次触发**。
- **覆盖**：需求 8.15、8.8。

## 第 3 组 · 播报编排在真机上的时序（iOS + Android 都要跑）

### 3.1 记账页：弹层能不能赶上 500ms 的返回

> **造解锁数据的办法**：用零数据的账号 B 连续记 10 笔有效账（有账本、非转账、未删除），
> 第 1 笔解锁 `FIRST_RECORD`、第 10 笔解锁 `RECORD_10`；要一次拿到更多可先记 10 笔再看，
> 或直接用一个已凑够条件的测试账号。

- **做什么**：在记账页保存一笔会触发解锁的账。
- **看什么**（这是本组的重点，因为记账成功后本页**通常在 500ms 内返回上一页**）：
  ① 「已记录」提示与**页面返回、列表刷新、余额刷新照常先发生**，**不等**播报请求
  （播报慢或失败都不能卡住这三件事）；② 弹层若来得及展示，它挂在记账页上；
  ③ 弹层**若因为页面已返回而没能展示**，则应当是**静默放弃**：不弹、不提示、**不推进游标**——
  于是这些成就**留在待播报集合内**；④ 接着打开**成长页**或**成就页**，那些成就**照常被播报出来**
  （这就是「至少一次」语义：漏播是事故，重播只是冗余）。
  两台机器都记录：弹层是「赶上了」还是「被放弃了」，以及第 ④ 步是否补播成功。
- **覆盖**：需求 7.1、7.12、7.10、7.11、7.14。

### 3.2 弹层内「进入成就页」

- **做什么**：弹层出现后点「进入成就页」。
- **看什么**：① **300ms 内**收起弹层并打开成就页；② **本次尚未展示的 Toast 被放弃**（不再蹦出来）；
  ③ 落地后**高亮刚播报的那一枚**（走的是与分享落地同一条 `?code=` 通路）；
  ④ 之后再打开成就页 / 成长页，**已展示过的那些成就不再重复播报**（游标已推进）。
- **覆盖**：需求 7.16、7.9、8.11。

### 3.3 成长页入口与成就页三态

- **做什么**：打开成长页；再断网打开成长页；再断网打开成就页；恢复网络后在成就页点重试、下拉刷新。
- **看什么**：① 成长页徽章墙**上方**有成就入口，计数形如 `8 / 16`；② 成长页数据请求失败/超时 →
  入口**不含计数**但**点进去照常打开成就页**；③ 未登录 → **不展示该入口**；
  ④ 成就页错误态**只有**失败文案 + 重试胶囊，**一个成就项都不渲染、不展示计数**，
  重试期间胶囊不可再次点；⑤ 成功后失败文案消失、按「起步 / 坚持 / 积累 / 协作 / 主题」五组渲染；
  ⑥ 距上次请求不足 3000ms 时下拉 → 不发请求、动效 1000ms 内结束、取值一行不动、无错误提示。
- **覆盖**：需求 9.1、9.14、9.15、9.7、9.8、9.9、9.10、9.16、9.3~9.6。

## 第 4 组 · 迁移的最终验收（老用户第一次打开不弹任何成就）

> 这是任务 1.1 游标回填的最终验收，也是本清单里**唯一会动数据库**的一项。
> **在测试环境做，不要在生产库上做。**

### 4.1 在有存量 `BADGE` 行的库上跑迁移，然后用老账号打开小程序

- **做什么**：
  1. 找一个**尚未应用 V33** 且 `growth_events` 里**已有 `BADGE` 行**的库（本次复核时
     `deploy/dev-remote-db.conf` 指向的测试库正处于这个状态：仍停在 V32、无 `achievement_notices` 表）。
     执行前先记录 `SELECT user_id, MAX(id) FROM growth_events WHERE event_type = 'BADGE' GROUP BY user_id`。
  2. 启动应用让 Flyway 应用 V33（`bash deploy/dev-remote-db.sh` 即可）。
  3. 核对 `SELECT * FROM achievement_notices`：行数等于第 1 步的用户数，每行
     `last_notified_event_id` 等于该用户的 `MAX(id)`，`created_at = updated_at`。
  4. 用**这些老用户中的一个**（账号 A）登录小程序，依次打开**首页 → 记一笔账 → 成长页 → 成就页**。
- **看什么**：**全程一个解锁弹层都不弹、一条成就 Toast 都不出**；成就页里那些历史成就**照常显示为
  已解锁**并带解锁日期。若有任何弹层出现，说明回填或待播报过滤出了问题——这是产品事故级缺陷。
- **覆盖**：需求 10.7、10.8（回填正确性）与需求 7.1~7.3（老用户不被轰炸）。

## 附录 B：一条与清单预期不符的既有结论（任务 1.4 已记录，此处提醒）

`'BADGE '`（**尾**空格）**不会**被 `ck_growth_events_type` 拒绝：该实例上 `utf8mb4_bin` 的
`PAD_ATTRIBUTE` 是 `PAD SPACE`，比较时忽略尾部空格。**语义无害**（这样的行在
`event_type = 'BADGE'` 的查询里照常被命中，且写入侧的取值全部来自 `GrowthEventType` 常量，
没有尾空格来源），因此**不改 DDL**。需求 10.6 明确列举的是「仅大小写不同的字符串」与空字符串，
这两类均已实测被拒。**不要**把「尾空格被拒」写进任何测试或验收预期。
